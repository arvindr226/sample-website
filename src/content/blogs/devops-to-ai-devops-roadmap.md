## The role is extending, not restarting

An AI DevOps engineer is first a strong operator. Linux, networks, delivery, cloud, Kubernetes, security, and observability remain the system of record for every useful AI workflow. The transition adds a second layer: programming, model literacy, retrieval, agents, safety, and evaluation.

> AI DevOps is DevOps expertise multiplied by AI reasoning, knowledge retrieval, controlled automation, human approval, and verification.

## A nine-stage sequence

| Stage | Focus | Evidence to build |
|---|---|---|
| 1 | DevOps foundations | Reproducible delivery pipeline |
| 2 | Kubernetes and platform | GitOps-managed application |
| 3 | Programming | Typed operational API client |
| 4 | AI fundamentals | Evaluated structured-output prompt |
| 5 | Embeddings | Semantic runbook search |
| 6 | RAG | Cited runbook assistant |
| 7 | Agents | Read-only triage workflow |
| 8 | AI DevOps | Evidence-based Kubernetes RCA assistant |
| 9 | Advanced safety | Policy, approval, and verification loop |

Do not wait to “finish AI” before building. Use each stage to improve one operational workflow. For example, a Python client can fetch Kubernetes events; embeddings can retrieve related runbooks; a graph can pause before suggesting a test.

## The first portfolio project

Build a read-only Kubernetes troubleshooting assistant. It should accept an incident scope, call typed tools for workloads and events, retrieve approved runbooks, then return three things:

1. An evidence timeline.
2. Ranked hypotheses with uncertainty.
3. Suggested diagnostic tests that do not mutate production.

Avoid giving it general shell or write credentials. A useful assistant does not need autonomy to demonstrate architecture judgment.

## What to measure

Measure retrieval relevance, citation correctness, time to first useful hypothesis, unsafe suggestion rate, and engineer acceptance. A polished demo without an evaluation set shows interface work; a tested workflow shows engineering.

## The durable advantage

Model providers and frameworks will change. The durable skills are system decomposition, telemetry quality, tool contracts, identity, policy, verification, and honest evaluation. Those are already DevOps strengths. The opportunity is to apply them to probabilistic components with the same rigor used for distributed systems.
